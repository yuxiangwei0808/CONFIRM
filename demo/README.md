# CONFIRM visual guide

An interactive walkthrough of a claim's analysis plan, results, five evidence
checks, and reporting decision. A separate recorded agent example shows how
CONFIRM evaluates follow-up proposals after a confound failure.

The site uses plain HTML, CSS, JavaScript, and checked-in JSON. It runs entirely
in the browser and requires no model credentials, server application, or cohort
downloads. All asset paths are relative, including when hosted at `/CONFIRM/`.

## Preview

From the repository root:

```bash
python -m http.server 8000 --directory demo/site
```

Open `http://localhost:8000`. Serve the folder over HTTP so the browser can load
the JSON files.

## Data and provenance

`site/data/examples.json` contains the three examples generated by
`confirm.demo`: a replicated association, an omitted site confound, and an
association that does not replicate. Each uses independent 600-observation
samples with fixed seeds. Plots show 180 observations per sample; the analyses
use all observations. Each example has downloadable plan and analysis JSON.

`site/data/followup.json` contains an aggregate export of a recorded agent run
on the benchmark control `neg_site_confound_ukb_s1`. The agent proposed a
site-adjusted version of the original analysis and an exploratory comparison
across related connectivity measurements. Both plans passed validation and
were evaluated; neither received support. The export includes original and
proposed plans, validation results, aggregate statistics, the recorded model
identifier, and a SHA-256 hash of the source checkpoint. It excludes participant
records, filesystem paths, and model prompts. This example is recorded playback.

Install CONFIRM from this checkout, then regenerate the synthetic examples:

```bash
python -m pip install .
python demo/prepare_data.py
```

This leaves the recorded follow-up unchanged. To refresh that export from its
original checkpoint, provide `--followup-source /path/to/parent_0002.json`.
The standalone site includes the exported record and needs no checkpoint access.

## Check the guide

```bash
python demo/validate.py
node --check demo/site/app.js
```

For browser checks, start the preview server above, then run in another terminal:

```bash
python -m pip install playwright
python -m playwright install chromium
python demo/check_browser.py http://localhost:8000
```

The browser checks exercise all example stages, reporting-standard decisions,
record downloads, follow-up playback, URL state, and five screen widths. Pass
`--screenshots /path/to/screenshots` to save desktop, mobile, results, and checks
views. The guide supports keyboard controls and reduced-motion preferences.

## GitHub Pages

The `demo/visual-guide` branch contains both the existing framework and this
guide. The visual-guide workflow validates and publishes only `demo/site`.
It runs when this branch changes; pull requests run validation without deployment.

Repository Pages settings must use **GitHub Actions**, and the `github-pages`
environment must allow deployments from `demo/visual-guide`. The site is served
at `https://yuxiangwei0808.github.io/CONFIRM/` after successful deployment.

To move publishing to `main`, update the workflow's push branch and deployment
condition, and allow `main` in the `github-pages` environment.
