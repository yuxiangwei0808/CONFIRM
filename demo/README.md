# CONFIRM project website

The homepage presents the paper's framework, authors, figures, main comparisons,
follow-up results, and NeuroClaimBench. The interactive walkthrough is at
`/guide/`, with three reproducible examples and a recorded agent follow-up.

The site uses plain HTML, CSS, JavaScript, and checked-in data. It needs no model
credentials, server application, or cohort downloads. The homepage is readable
without JavaScript. Asset paths work both at the domain root and under `/CONFIRM/`.

## Preview

From the repository root:

```bash
python -m http.server 8000 --directory demo/site
```

Open `http://localhost:8000` for the project page or
`http://localhost:8000/guide/` for the walkthrough. Serve the folder over HTTP
so the guide can load its JSON records.

## Paper figures and results

`site/figures/` contains four vector figures exported from the paper's PDFs.
Lettering is stored as vector paths so the figures render consistently without
requiring the original fonts. `site/paper-data/` contains the comparison CSVs,
extracted results, and a manifest with source filenames and SHA-256 hashes. The homepage's
follow-up table uses the paper's representative run. Its notes define the
search-data count and holdout percentage separately.

To import updated figures and results from a paper source directory:

```bash
python -m pip install PyMuPDF==1.26.5
python demo/import_paper.py /path/to/paper
```

The importer reads four PDFs, two comparison CSVs, and
`figures/tab_feedback_control_main.tex`. It does not modify the paper. Update
the homepage's text and table when the reported results change; validation
checks the table against the extracted data and the comparison claims against
the source CSVs. The published site includes all required assets and runs
without the paper source directory.

## Guide examples

`site/guide/data/examples.json` contains the three examples generated by
`confirm.demo`: a replicated association, an omitted site confound, and an
association that does not replicate. Each uses independent 600-observation
samples with fixed seeds. Plots show 180 observations per sample; the analyses
use all observations. Each example has downloadable plan and analysis JSON.

`site/guide/data/followup.json` contains an aggregate export of a recorded agent
run on the benchmark control `neg_site_confound_ukb_s1`. The agent proposed a
site-adjusted analysis and a comparison across related connectivity measurements.
Both plans passed validation; neither received support. This is a separate
example from the successful OASIS3 follow-up on the project homepage.

The export includes plans, validation results, aggregate statistics, the model
identifier, and a SHA-256 hash of the source checkpoint. It excludes participant
records, filesystem paths, and model prompts. Playback makes no model calls.

Install CONFIRM from this checkout, then regenerate the synthetic examples:

```bash
python -m pip install .
python demo/prepare_data.py
```

This leaves the recorded follow-up unchanged. To refresh that export from its
source checkpoint, add `--followup-source /path/to/parent_0002.json`.

## Validation

```bash
python demo/validate.py
node --check demo/site/project.js
node --check demo/site/guide/app.js
```

For browser checks, start the preview server above, then run in another terminal:

```bash
python -m pip install playwright
python -m playwright install chromium
python demo/check_browser.py http://localhost:8000
```

The browser checks cover the homepage's figures and results, navigation between
pages, old guide URLs, all example stages, reporting decisions, downloads,
follow-up playback, keyboard controls, and five screen widths. They also check
that the homepage works without JavaScript. Add
`--screenshots /path/to/screenshots` to save desktop and mobile views.

## GitHub Pages

The `demo/visual-guide` branch contains the framework and website. The
`Project website` workflow validates and publishes only `demo/site`. Branch
pushes deploy the site; pull requests run validation without deployment.

Repository Pages settings must use **GitHub Actions**, and the `github-pages`
environment must allow deployments from `demo/visual-guide`. The project page
is served at `https://yuxiangwei0808.github.io/CONFIRM/` and the guide at
`https://yuxiangwei0808.github.io/CONFIRM/guide/`.

Links to the original guide URL that contain an `example`, `step`, or `standard`
query parameter redirect to `/guide/`, preserving the selected state.

To publish from `main`, update the workflow's push branch and deployment
condition, and allow `main` in the `github-pages` environment.
